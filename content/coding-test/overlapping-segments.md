## 문제

평행하게 놓인 선분 3개의 시작과 끝 좌표가 `[[start, end], [start, end], [start, end]]` 형태의 배열 `lines`로 주어진다. 두 개 이상의 선분이 겹치는 부분의 길이를 return 한다.

- `lines`의 길이는 3
- 모든 선분은 길이가 1 이상
- `-100 ≤ a < b ≤ 100`

| lines                       | result |
| --------------------------- | ------ |
| `[[0, 1], [2, 5], [3, 9]]`  | `2`    |
| `[[-1, 1], [1, 3], [3, 9]]` | `0`    |
| `[[0, 5], [3, 9], [1, 10]]` | `8`    |

직접 추가한 테스트 케이스도 통과한다. 선분끼리 끝점에서만 닿아 겹친 길이가 0인 경우로, 점을 세는 방식으로는 1이 나오는 반례다.

| lines                       | result |
| --------------------------- | ------ |
| `[[-1, 0], [0, 1], [1, 2]]` | `0`    |

## 접근

점을 세면 끝점끼리 닿기만 한 경우와 실제로 겹친 경우를 구분할 수 없다. 그래서 좌표 `x`를 점이 아니라 `x ~ x+1` 칸으로 보고, 같은 칸이 두 번 이상 나오면 길이 1만큼 겹친 것으로 센다.

1. 각 선분을 `start`부터 `end - 1`까지의 칸으로 쪼개 `counts`에 넣는다.
2. `filter`로 두 번 이상 나온 칸만 한 번씩 남긴다.
3. 남은 칸의 개수가 곧 겹친 길이다.

칸 개수를 N이라 할 때 `filter` 안의 `indexOf`·`lastIndexOf` 때문에 O(N²)이다. N은 최대 600이라 충분하다.

## 코드

```js
function solution(lines) {
  const counts = [];

  for (const [start, end] of lines) {
    for (let x = start; x < end; x++) {
      counts.push(x); // x ~ x+1 칸
    }
  }

  const duplicates = counts.filter(
    (count, index) =>
      counts.indexOf(count) !== index && counts.lastIndexOf(count) === index,
  );

  return duplicates.length;
}
```

## 다른 풀이: 배열로 칸 세기

좌표 범위가 `-100 ~ 100`이므로 길이 200인 배열에 인덱스를 `+100` 옮겨 칸마다 덮인 횟수를 센다. 반복이 칸 수만큼이라 O(N)이다.

```js
function solution(lines) {
  const line = new Array(200).fill(0);

  for (const [start, end] of lines) {
    for (let x = start; x < end; x++) {
      line[x + 100]++;
    }
  }

  return line.filter((count) => count >= 2).length;
}
```

## 끝점을 빼도 되는 이유

칸 하나를 왼쪽 숫자로 부르기로 했으므로, `[2, 5]`는 2·3·4 세 칸으로 2부터 5까지 빈틈없이 덮인다. 끝점 5는 이미 4번 칸의 오른쪽 끝에 포함되어 있고, 5번 칸(5~6)은 선분 바깥이다. 칸 개수 `end - start`가 선분 길이와 정확히 같다는 점으로도 확인할 수 있다.

```
2   3   4   5
|■■■|■■■|■■■|
 x=2 x=3 x=4
```

끝점끼리 닿는 `[[0, 1], [1, 2], [2, 3]]`은 0·1·2 칸이 한 번씩만 나오므로 겹친 길이가 0이 된다.

## 회고

좌표를 점이 아니라 선(칸)으로 봐야 한다는 점이 가장 어려웠다. 처음에는 선분에 포함된 점을 모두 넣고 중복된 점이 연속되는지로 길이를 구하려 했는데, 이렇게 하면 겹친 점 사이 구간이 실제로 두 선분에 덮였는지 알 수 없다. 숫자 `x`를 `x ~ x+1` 칸으로 바꿔 생각하고 나서야 끝점을 빼는 이유와 연속 여부를 따질 필요가 없는 이유가 함께 이해됐다.
